STM32H755 · C / C++

ARM Cortex-M7 Real-Time Kernel

A lightweight preemptive RTOS kernel built on static allocation, with priority scheduling across 32 levels, O(1) ready lists, and dynamic-tick timekeeping.

Challenge Designing a preemptive RTOS from scratch required scheduling, context switching, synchronisation, mutex priority inheritance, and memory safety without relying on an existing operating system.

Approach I broke the system into smaller kernel mechanisms and implemented them incrementally: priority scheduling, mutexes, semaphores, queues, and task notifications.

Learning Real-time systems are not only about speed. Timing guarantees, concurrency, and failure modes need to be designed into the system from the beginning.

Outcome The kernel developed into a functional real-time system. Building it from the ground up also highlighted areas of concurrency and low-level processor behaviour that I continue to deepen.

STM32F446 · Register-level C

Bare-Metal Driver Library

Peripheral library written without STM32 HAL/LL dependencies, covering RCC, GPIO, EXTI, NVIC, SysTick, PWR, ADC, DMA, and modular timer drivers.

Challenge Developing peripheral drivers without STM32 HAL/LL required understanding the microcontroller at register level instead of relying on abstraction layers.

Approach I implemented functionality incrementally, using the reference manual and datasheet while developing startup code, linker configuration, peripheral drivers, and the debugging workflow.

Learning I gained a stronger understanding of how software interacts with hardware through registers, interrupts, clocks, DMA, and memory configuration.

Outcome The library provided working low-level interfaces for the implemented peripherals, while making the added debugging effort behind higher-level libraries clear.

STM32L476RG

Low-Power Optical Data Acquisition System

Firmware for a battery-operated optical data logger designed for autonomous operation.

Challenge The system needed autonomous, low-power operation while producing reliable measurements, requiring sampling, calibration, power management, fault handling, and logging to work together.

Approach I designed firmware around a state machine using RTC scheduling, Stop 2 mode, watchdog recovery, differential sampling, temperature compensation, and persistent fault handling.

Learning Embedded reliability comes from considering the whole system, rather than treating acquisition, power, timing, and fault handling as separate problems.

Outcome Based on the implemented and tested functionality, the design operated as intended and strengthened my confidence in firmware for autonomous operation.

MATLAB · Simulink · Stateflow

Autonomous Micromouse Navigation

An autonomous maze-navigation and motion-control system.

Challenge The robot had to navigate an unknown maze while estimating its position, following walls, and determining efficient routes despite imperfect sensors and motion.

Approach I used depth-first search with backtracking to explore the maze and breadth-first search to determine a shortest path after mapping. PID control and sensor fusion from wheel encoders, gyroscope measurements, and time-of-flight sensors supported movement and wall following.

Learning A mathematically correct algorithm still has to contend with sensor noise, positioning error, control error, and mechanical behaviour in a physical system.

Outcome The navigation and control approach worked in principle, while exposing the practical limitations of sensor-based autonomous control and the gap between an ideal algorithm and physical implementation.
